# gitcask context

Gitcask backs up GitHub repos to R2 on a schedule. One Worker (`src/index.ts`) serves the admin API, the landing page, a queue consumer, and a 5-minute cron. Backups themselves run in a container (`container/server.ts`) reached through a Durable Object.

## Backup lifecycle

A job moves `queued → running → completed | failed` (cancel also ends in `failed`). All job state transitions live in `src/services/job-lifecycle.ts`; add new ones there, not inline in routes.

1. **Enqueue.** Either path inserts a `queued` job row and sends a `QueueMessage` to `JOB_QUEUE`:
   - manual: `POST /repos/:id/trigger` in `src/routes/repos.ts`
   - scheduled: the cron's `handleScheduledEvent` in `src/services/scheduler.ts`, which skips repos whose GitHub `pushed_at` hasn't changed (`src/services/change-detection.ts`)
2. **Consume.** `src/queue/consumer.ts` marks the job `running` (`markRunning`), then calls `dispatch` in `src/services/backup-dispatcher.ts`. If dispatch fails, `recordFailure` either re-enqueues with a delay or sends the `backup.failed` webhook.
3. **Back up.** `BackupContainer` (`src/container.ts`) starts the container and forwards the request to port 8788. The container mirror-clones the repo, then uploads to R2 **directly over the S3 API** using the `r2_credentials` in the request:
   - `repos/{owner}/{name}/snapshots/{ts}_{job}.tar.gz`
   - a `_metadata.json` sibling holding GitHub metadata

   It reports each stage to `/internal/jobs/:id/progress`. Keep the tar.gz shape; dropping it was considered and rejected.
4. **Complete.** The container calls `/internal/jobs/:id/complete` (`src/routes/callback.ts`). On success the callback route writes the run and artifact rows, then writes `repos/{owner}/{name}/latest.json` **through the `BUCKET` binding**.
5. **Sweep.** Every cron tick, the scheduler fails `running` jobs that are past `deadline_at` (15 min), and `src/services/retention.ts` prunes artifacts and old run rows.

## Where things live

- `src/routes/`: Hono routes. `/health` is public. The admin API (`/repos`, `/runs`, `/jobs`) and `/internal/jobs` (container callbacks) are guarded by `adminAuth` (`src/lib/auth.ts`, the `ADMIN_TOKEN` bearer).
- `src/db/schema.ts`: D1 tables `repos`, `jobs`, `runs`, `artifacts`. Migrations are in `drizzle/`, generated by `bun run db:generate`.
- `src/types.ts`: `Env` bindings plus the queue, container, and callback payload shapes. It is the contract between the Worker and the container.
- `src/landing/`: static landing page, imported as text modules.
- `cli/`: the `gitcask` admin CLI, an HTTP client over the admin API.
- `container/`: the backup service, with its own `package.json`. `@aws-sdk/client-s3` is used only here, so knip's `--production` flag reports it as unused even though it isn't.
- `scripts/r2-migrate-keys.ts`: a one-shot migration, pending deletion (#28).

Production, secrets, and R2 verification: `docs/ops.md`.
